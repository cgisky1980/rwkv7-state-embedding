# 0.1B 模型路由/相似度实验记录

**日期**: 2026-09-07
**目标**: 用最小模型 `rwkv7-g1d-0.1b`（官方 albatross）验证 STS 相似度与分类/路由两项任务表现，与 0.4B 对比。

## 0.1B 模型结构（已加载验证）

| 项 | 值 |
|----|----|
| 模型 | `rwkv7-g1d-0.1b-20260129-ctx8192.pth` (364.5 MB) |
| n_layer | 12 |
| n_embd | 768 |
| n_head | 12（head_size=64, state_dim=12×64×64=49152） |
| vocab | 65536 |

与 0.4B（L=24, C=1024, H=16）同系 g1d，head_size 恒 64，可被同一 albatross `rwkv7.py` 加载。提取层用 **layer=11**（0-based 最后一层）。

## 运行方式

- 特征提取层：`--layer 11`（0.1B 为最后一层；0.4B 用 layer=12 为中间层）
- 缓存目录独立：`cache_python_0.1b/`（避免与 0.4B 的 `cache_python/` 冲突）
- 提取命令：
  ```
  run_with_msvc.bat extract_features.py --task sts --layer 11 --sts-subdir sts_dedup --out-dir ..\cache_python_0.1b --model-path ..\models\rwkv7-g1d-0.1b-20260129-ctx8192.pth
  run_with_msvc.bat extract_features.py --task classification --layer 11 --out-dir ..\cache_python_0.1b --model-path ..\models\rwkv7-g1d-0.1b-20260129-ctx8192.pth
  ```

## 脚本适配（兼容 0.1B，不破坏 0.4B）

1. `extract_features.py`: 新增 `--model-path`、`--out-dir` 参数（默认仍 0.4B / cache_python）。
2. `02_sts_similarity.py`: 新增 `--layer` 参数（默认 12），缓存文件名/投影保存引用改用 `args.layer`。
3. `03_classification.py`: head 数从 `state_dim/(head_size²)` 动态推导（兼容 16/12 head），不再硬编码 `NUM_HEADS=16`。

## MTEB STS 泄露审计与去泄露重训（重大发现）

**日期**: 2026-09-08

### 1. 泄露发现

用 `universal_projection_l11.pt`（0.8140 那版投影器）跑 MTEB STS，多数任务飙到 0.95+（SICK-R 0.959、STS12 0.967、HUMESTS12 0.989），异常于泛化能力。审计训练数据来源后确认**数据泄露**：

- **extra_train (21943 对) = 100% MTEB 测试集**（历届 STS12-16 test + SICK test，句子级全量命中）
- **sickr (9927 对) = 100% SICK-R 测试集**
- sts_train 中 43 对与 STS-B test/dev 句子重叠（0.8%）
- nli_train 基本干净（仅 1 对命中）

审计方法：收集 MTEB eng STS 全部任务 eval split 句子（32006 句）建 block 集合，句子级精确匹配过滤（`filter_leakage.py`，临时脚本已删除，逻辑：sentence1/sentence2 任一命中即剔除该对）。

**结论**：0.8140 投影器在 MTEB 的 STS12-16/SICK-R/HUME 系列上的分数全部无效（纯记忆）；但其在 **STS-B test 的 0.8140 依然基本成立**——SICK/STS12-16 属于不同数据集，对 STS-B 是合法的跨数据集迁移训练（仅 43 对直接重叠，可忽略）。

### 2. 去泄露重训（clean 投影器）

- **训练数据**: STS-B train 5033 对（剔除 43 泄露对）+ NLI 9951 对 = **14984 对**（原 47k 中 32k 是测试集）
- **配置**: 与最优版一致（hidden 特征 768 维，h1024/out512/drop0.1，AnglE τ=0.5，5 seed 集成）
- **缓存**: `paper/cache_python_0.1b_clean/`（仅存 hiddens+scores）
- **投影器**: `paper/cache_python_0.1b/universal_projection_l11_clean.pt`
- STS-B test：无监督 0.4509 → clean 投影 5 seed 集成 **0.5719**（泄露版 0.8140 的差距来自 SICK/extra 跨数据集迁移，属合法但不可用于 MTEB 评估）

### 4. state 特征提取对比：整层 MLP vs Top-K Head（paper §4.3.4 方法）

**背景**：先试了把整层 state（49152 维 = 12 head × 64×64）直接进 MLP（49152→1024→512，约 50M 参数），结果严重过拟合——STS-B test 无监督 0.5158 → 投影后单模型均值仅 0.4977（低于无监督），5 seed 集成 0.5454；50M 参数 vs 15k 对数据明显不匹配。MTEB 上部分任务甚至低于裸 hidden（BIOSSES 0.224 vs 0.572）。

**正确做法（paper §4.3.4 分类任务同款方法，移植到 STS）**：
1. 逐 head 评估：每 head 的 state（4096 维）单独 PCA64 + 小投影器（256/128, 10 epochs, seed 42）→ dev Spearman 排序（只用 dev，不接触 test）
2. 选 Top-8 head 拼接（8 × 4096 = 32768 维）
3. PCA 降维到 256（randomized, train 句子行上 fit）
4. 正式投影器 MLP（256→1024→512，AnglE，5 seed），同 clean 配置

**head 有效性**（dev Spearman，12 个 head）：H5 **0.703** / H9 0.702 / H3 0.646 / H0 0.634 / H6 0.623 / H8 0.583 / H1 0.581 / H4 0.564 | 落选：H7 0.531 / H11 0.526 / H2 0.518 / H10 0.494。head 间差异显著（0.49-0.70），验证 head 选择的必要性。

**STS-B test 内部对比**：

| 特征 | 无监督 cosine | 投影后（5 seed） |
|------|------------|----------------|
| hidden 768 维 | 0.4509 | 0.5719 |
| 整层 state 49152 维 | 0.5158 | 0.5454（过拟合） |
| **Top8 head + PCA256** | **0.6305** | **0.6724** |

注意 Top8+PCA256 的**无监督** cosine 就已达 0.6305（PCA 去各向异性本身就大幅提升 state），监督投影再 +0.04。

**结论**：
1. **Top-K Head 方法对 STS 同样有效**：Top8+PCA256 的 state 投影器核心平均 **0.664**，超过 hidden 投影器（0.658），成为 0.1B 最优配置。
2. 整层 state 直接进 MLP 是错误做法（过拟合），印证 paper Top-K Head 设计的必要性；正确提取后 state 的 STS 潜力**优于** hidden。
3. 对 paper 的补充发现：§4.3.3 "WKV state 聚类效果远低于 hidden（0.11 vs 0.29）"是在**无监督聚合统计量**语境下的结论；对 STS 任务，在监督 Top-K Head + PCA 框架下，state（0.664）反超 hidden（0.658）。两者不矛盾：state 的语义信息集中于少数 head，且各向异性可用 PCA 缓解。
4. 例外：HUMESTS22（短文本、多领域）上 Top-K state（0.496）明显低于 hidden 投影（0.682），该类任务更依赖 hidden 的全局语义。
5. 训练成本对比：Top-K head 版 PCA 后仅 256 维，每 seed 2.6s（整层 49152 维版每 seed 123s），训练快 47 倍。

## 5. 百万对级数据扩充实验（2026-09-08）

**动机**：clean 投影器仅 15k 对训练（STS-B train 5k + NLI 采样 10k），与专用嵌入模型（bge/e5 约 1 亿对）差距 60 倍量级。目标：合法扩到 ~95 万对，验证数据规模对 clean 投影器的提升。

### 1. 数据收集（`scripts/collect_million_sts.py`）

全量下载 SNLI + MultiNLI train split（不复用旧 `data/sts_dedup/nli_train.jsonl`，它只是两者的前 5k 采样），标签→分数映射沿用既有口径：entailment=5.0 / neutral=3.0 / contradiction=2.0。

| 数据集 | 原始 | 无标签 | 对级重复 | 转换后 |
|--------|------|--------|---------|--------|
| SNLI | 550,152 | 785 | 652 | 548,715 |
| MultiNLI | 392,702 | 0 | 140 | 392,562 |
| **合计** | | | | **941,277** |

分数分布均衡（contradiction/neutral/entailment 各约 1/3）。

### 2. 泄露过滤（MTEB 句子级 blocklist）

重建 MTEB eng STS 全部 17 任务 eval split 句子集合（31,318 句），句子归一化（strip+lower）精确匹配过滤：

| 数据集 | 过滤前 | 剔除 | 过滤后 |
|--------|--------|------|--------|
| SNLI | 548,715 | 4,732 | 543,983 |
| MultiNLI | 392,562 | 5 | 392,557 |

SNLI 剔除 4,732 对（0.86%）——SNLI premise（Flickr caption）与 MTEB SICK 系列句子同源重叠，符合预期；MultiNLI 基本干净。

**最终训练集 = STS-B train 5,033（clean）+ SNLI 543,983 + MultiNLI 392,557 = 941,573 对**（旧 nli_train 弃用，已含于全量）。数据/报告：`data/sts_million/{snli,multinli}_train_{full,clean}.jsonl`、`report.json`。

### 3. hidden-only 提取改造

百万对若同时提 state（49152 维 fp16）需 ~130GB 内存/磁盘，不可行。改造：
- `lib/cache.py` save_npz 支持 states=None
- `lib/albatross_wrapper.py` extract_features_batch 加 `need_state` 参数（跳过 state 数组分配与 GPU→CPU 拷贝）
- `extract_features.py` 加 `--hidden-only`、`--sts-names` 参数

提取（0.1B，layer 11，batch 64）：**~4,000 句/秒**（state 模式约 10 倍速），SNLI 1.6GB + MultiNLI 1.15GB，全程约 7 分钟。缓存：`cache_python_0.1b_clean/sts_pair_l11_{snli,multinli}_train_clean.npz`。

### 4. 训练结果（STS-B test）

配置与 clean 最优版一致（hidden 768，h1024/out512/drop0.1，τ=0.5，50 epoch，dev 早停，5 seed，GPU，batch 4096），每 seed ~197s。

| 训练数据 | pairs | 单模型均值 | 5 seed 集成 |
|---------|-------|-----------|------------|
| clean 15k（STS-B + NLI 采样） | 14,984 | — | 0.5719 |
| **百万对（STS-B + SNLI + MultiNLI）** | 941,573 | 0.5504 | **0.5716** |

### 6. 结论与教训

1. **单纯堆 NLI 数据量无效且有害**：数据 ×63 后 STS-B test 持平（0.5716 vs 0.5719），MTEB 核心平均反降 0.053（0.658→0.605）。
2. **根因：离散分数稀释**。NLI 映射只有 2/3/5 三个离散值（94 万对），STS-B 连续分数仅 5k 对（占比从 15k 版的 1/3 跌到 1/190）。MTEB STS 任务全部是细粒度连续分数（Spearman 排序敏感），模型被训练成粗粒度三分类器——细粒度任务（BIOSSES -0.149、HUMESICK-R -0.148）掉得最狠，短文本多领域（HUMESTS22 +0.044）反而受益于 NLI 多样性。
3. **对 paper 观点的印证**：监督信号的「质量/粒度」比「数量」更重要。bge/e5 的亿级训练对不是 NLI 离散标签，而是带连续相关性信号的检索式正负例（in-batch negatives + 温度超参）。
4. **可行后续**（按优先级）：
   - 两阶段：94 万 NLI 预训练（粗粒度语义对齐）→ 15k（STS-B+NLI）微调（细粒度排序）
   - 上采样 STS-B 连续分数（~×50）恢复监督比例
   - 检索式对比训练（in-batch negatives，对齐主流嵌入模型范式）

## 6. 检索式数据 + InfoNCE 两阶段训练（2026-09-08）

### 2. 训练范式

## 7. state / fusion 特征的 InfoNCE 两阶段训练（2026-09-08）

**动机**：§6 的两阶段最优仅用 hidden 特征（0.708）；§4 已证明 Top8-head state 投影在 clean 15k 下超过 hidden（0.664 vs 0.658）。两者信号互补（state 强在 STS16/HUMESICK-R，hidden 强在 HUMESTS12/22），验证 339 万检索式数据下 state 通道及 hidden⊕state 融合的增益。

### 1. 工程改造

- **state 落盘难题**：339 万对全量 state 需 ~700GB，不可行。解法：`extract_features.py --state-pca-from` 提取时**实时**套用已有 Top8 head 选择 + PCA256 变换，states 槽只存 256 维（全量 ~15GB）。
- 重提 12 数据集共 6.77M 文本（~2.6h，1400-3000 samples/s）→ `cache_python_0.1b_retrieval_state/`。
- `07_retrieval_infonce.py --feature state|fusion`：检索缓存按特征构建（state=低维 PCA 特征，fusion=hidden⊕state 拼接）；dev 集用 `--state-pca-from` 同源变换。
- `02_sts_similarity.py --state-pca-from`：复用同一份 head 选择 + PCA，保证 fusion 与单 state 投影**中间数据完全一致**。

### 2. 训练结果（同 §6 两阶段流程：339 万 InfoNCE 预训练 → clean 15k AnglE 微调 5 seed）

| state Top8+PCA256 (256) | 0.8092 | 0.7342 |
